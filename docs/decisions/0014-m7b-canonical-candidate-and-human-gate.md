# ADR 0014: Publish a reproducible development candidate before any training

- Status: accepted for M7B technical candidate
- Date: 2026-08-27
- Scope: canonical scripted-oracle SFT data and human review gate

## Context

M7A can reconstruct 18 train-only demonstrations from a complete 30-cell system-correctness Eval
and reject jointly re-signed content that is not derived from the supplied source evidence. Its
outputs were temporary. A later experiment would otherwise have no fixed sample bytes, data card,
or stable review target.

Automated schema, leakage, source-binding, and determinism checks answer technical questions. They
do not decide whether an instruction is clear, whether a sequence is a useful demonstration, or
whether a person considers the sample suitable. Codex helped prepare and verify this repository;
calling that work human review would misstate who made the judgment.

## Decision

Generate the canonical candidate from an export of public commit
`8a4016a9c154238cd7e5df5d1a3ed8fd194dd10d` that contains no `.git`. Build a pure wheel from that
export, install it in a new runtime environment, run a fresh 30-cell source Eval, and write the
four generated files directly to `datasets/sft-development-v1/candidate/`. Repeat the complete
source-Eval and candidate run in separate new directories and require exact relative paths,
lengths, SHA-256 values, and bytes.

Keep the generated manifest honest: `stage=development_candidate` and `exporter_commit=null` remain
unchanged. A commit field inside a file cannot truthfully name the commit that first contains that
same file without creating a self-reference. Public generator attribution therefore lives in Git
history, the data card, repository regression, and CI rather than in a rewritten generated
manifest.

The frozen generated report also says `not a tracked dataset`. Treat that sentence as an M7A
generation-time boundary: the M7A exporter only creates a caller-owned temporary candidate. M7B
versions the exact generated bytes in Git so reviewers can name and reproduce them; it does not
change the exporter contract, `stage=development_candidate`, or `exporter_commit=null`. Git
tracking is evidence attribution; the samples remain not training-ready and have no human
approval yet.

Preserve the four canonical files with one narrow Git `-text` rule. Data card and review Markdown
remain ordinary UTF-8/LF text. The source-bound validator remains the semantic authority; hashes
alone are consistency evidence, not signatures.

Pre-register six review samples without looking for favorable content. For each environment, sort
sample IDs by `(casefold, original)` and take the first and last. The review packet copies only the
canonical public instruction, allowed tools, ordered arguments, result status, and public payload.
Its issues and conclusion remain `pending human review` until the user actually reviews them.

Do not start model selection, API/GPU work, tokenization, DPO, SFT/LoRA training, or task expansion
in M7B. A reproducible candidate and completed automated gates do not make the data training-ready.

## Consequences

- Later work can identify one exact 18-sample, 60,967-byte development snapshot.
- A fresh public-wheel reproduction can detect a generated-file or platform drift before training.
- The data card exposes provenance, license, public fields, exclusions, intended use, and limits in
  one place without changing the frozen M7A contract.
- Review selection cannot be changed after inspecting content; the repository test recomputes the
  six IDs and compares every displayed review turn with the canonical samples.
- M7B must stop after technical review. A separate, real user decision is required before the
  review status changes or the candidate can be fixed in a commit.

## Rejected alternatives

- Generating from the M7B working tree was rejected because it would blur public generator source
  with documentation added after M7A.
- Copying an old temporary bundle or rewriting its source commit was rejected because neither is a
  fresh reproduction.
- Adding an in-band exporter commit was rejected because it would require editing generated bytes
  and create a self-referential attribution problem.
- Letting an AI select attractive examples or approve the packet was rejected because automated
  review is not human judgment.
- Starting training to “test the data” was rejected because model and training choices are outside
  this milestone and would make failures harder to attribute.
